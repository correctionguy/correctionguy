# Claude Code

- Claude Code reads `AGENTS.md` and `.claude/AGENTS.md` in the working directory and above it only when no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` exists there: the **Project instructions** setting (`pluginConfigs["agents-md@builtin"].options.instructionFiles`, honored in user or managed settings only) defaults to `claude-md-or-agents-md`; `~/.claude/CLAUDE.md`, the managed `CLAUDE.md`, and `.claude/rules/` load beside it either way. Never add a `.claude/CLAUDE.md` import shim, because it counts as a project `CLAUDE.md` and switches `AGENTS.md` reading off [source: https://code.claude.com/docs/en/memory]
- Direct `AGENTS.md` reading needs Claude Code v2.1.277 or later, the built-in `agents-md` plugin enabled, and a session that fetched feature flags, so the first session after an install or upgrade and a Bedrock or telemetry-disabled session skip it. `AGENTS.local.md`, `AGENTS.override.md`, and `.agents/` are never read [source: https://code.claude.com/docs/en/memory]
- Claude Code re-reads the user settings `env` block while a session runs: a new or changed `CORRECTIONGUY_*` key reaches later hook subprocesses and Bash commands, and a removed key stays set until restart. Verify an effective value in a fresh session, or read `turn_context` (`model`, `effort`) in the newest `~/.codex/sessions/<y>/<m>/<d>/rollout-*.jsonl` with `originator: codex_sdk_ts`
- On `SessionStart` a hook `systemMessage` lands in the transcript as model context, and `SessionStart` fires on startup, resume, clear, compact, and fork, so text in both `systemMessage` and `additionalContext` is injected twice per fire. `SESSION_START` goes in `additionalContext` only, with a one-line pointer in `systemMessage`; the short live-monitor correction keeps both fields [source: https://code.claude.com/docs/en/hooks.md]
- `PreToolUse`, `PostToolUse`, and `PostToolBatch` fire inside subagents with `agent_id` and `agent_type` set. Inside a subagent the subagent log is `<session-id>/subagents/agent-<agent_id>.jsonl` beside the parent file, or one level deeper under a spawn-specific directory (Workflow spawns land in `subagents/workflows/wf_<id>/`), so `scripts/correctionguy-hook.ts` searches `subagents/` recursively. The subagent end event is `SubagentStop`, which the plugin does not register, so `PostToolBatch` is the only reviewer channel there. Only `SubagentStop` input carries `agent_transcript_path`, the subagent's own log, so a `SubagentStop` handler reads that field instead of searching; see [[reviewer]] [source: https://github.com/correctionguy/correctionguy/pull/18]
- Claude Code writes each parallel tool call of one model response as its own assistant transcript record, and those records share one `message.id`. `liveMonitorContext` in `scripts/core.ts` counts distinct `message.id` values among assistant records that hold a `tool_use` block, and a record without an id (every Pi record) counts once. Never count tool calls or records: a parallel batch then steps past a cadence multiple and the scheduled review never runs [source: https://github.com/correctionguy/correctionguy/pull/64]
- The transcript file can lag behind the final reply when `Stop` fires, and the hooks reference names the `Stop` input's `last_assistant_message` as the source for that reply. `stopReviewContext` in `scripts/core.ts` uses it first and scans the transcript only when it is empty, which it always is on Pi, so never put the transcript scan first [source: https://github.com/correctionguy/correctionguy/pull/68]
- Every correction is prefixed `[for <agent_id or session_id>]` as a forensic marker. A recipient does not know its own id, so the tag is never a discard key
- A hook cannot set the session title: `session_title` appears only on `SessionStart` input, the name changes only through `/rename` or the internal auto-title, and an appended `custom-title` record moves nothing until load or resume. A hook can set only the terminal tab title through an OSC sequence on the TTY, and the Bash tool has no TTY. The prompts carry no title, `session_title`, or `/rename` mention [source: https://code.claude.com/docs/en/commands]
