# Reviewer

- Every surface (`SESSION_START`, stop check, live monitor, `skills/correctionguy/SKILL.md`) flags six failures and taste; a new flag must be one of those or it does not go in. A stranger installing the plugin on an unrelated repo must not receive one owner's rules, so an owner preference or repo procedure is enforced only through the missed-requirement flag when an instruction file defines it
- Retired and never re-added as flags or preamble lines: drift, wiping the user's work, todo drift, info-bombing, BS talk, ship vocabulary, workflow model sizing, `.memory` layout mechanics, write-side memory nudges, secret checks, and the agent-facing no-nitpick and ask-for-review lines. Never restore a deleted general-discipline rule to `AGENTS.md` or a prompt on the theory that the reviewer needs it
- User's Claims recorded in `.memory` count as checked. The reviewer's no-nitpick bar sits on top of the six: extreme, integrity-harming violations only, "ok" when in doubt. A taste go-further finding is a nudge, never a block
- The per-host `instructionFiles` string in `scripts/prompts.ts` is how the reviewer reaches rules. Claude names `AGENTS.md`, `.claude/AGENTS.md`, `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`, `.claude/rules/`, `~/.claude/CLAUDE.md`, and `~/.claude/rules/` [source: https://code.claude.com/docs/en/memory]; Pi names `AGENTS.md`, `CLAUDE.md`, `~/.pi/agent/AGENTS.md`, and `~/.pi/agent/CLAUDE.md` (the installed package's `dist/core/resource-loader.js`). A new location a host loads goes into that list, not into a flag
- Both reviewer prompts require a correction addressed to the agent, verb first ("Do not send notification", "Run tests before claim"): a tenseless fragment such as "Claude send no notification" reads as "sent none" and the agent does the opposite. The rule is reviewer-side only and needs no `skills/correctionguy/SKILL.md` sync
- A secret is a value with a token shape (API key, token, password, private key string); a variable name alone is public. Never re-add a reviewer-side secret or memory flag; the agent-facing secret wording lives in `skills/setup/SKILL.md`
- The `Stop` handler in `scripts/correctionguy.ts` holds back a nudge when the same correction text already fired in the session inside `NUDGE_COOLDOWN_MS`, keyed by the correction text in one tmpdir JSON file per session named by a SHA-256 of the session id (Pi accepts non-UUID session ids). A block is never held back, and the reviewer still runs on every Stop
- The `Stop` handler reads the nudge state file (`correctionguy-nudges-<sha256 of session id>.json` in the OS tmpdir) with `NudgeState.parse` inside its `try`, so a corrupt or wrong-shaped file throws and trips the session review breaker. The file is never rewritten: on Claude Code each `SessionStart` clears the marker and the next nudge trips it again, and on Pi reviews stay off. The logged error does not name the file; delete it to recover [source: https://github.com/correctionguy/correctionguy/pull/33]
- The live-monitor context holds only `current_tool_batch`, `latest_assistant_message`, and `recent_transcript`. Never re-add a `todos` field or a `Task #N created successfully:` parse: Claude Code sessions started through the SDK entry point expose no `TaskCreate`, `TaskUpdate`, or `TodoWrite` tool, Pi has none, and the parse ran on every tool result, so any tool output with that text became a false pending task [source: https://github.com/correctionguy/correctionguy/pull/59]
- The per-repo `.memory` opt-out is a line in an instruction file the host loads, and `SESSION_START` and the `/correctionguy` skill yield to it. Never add a `CORRECTIONGUY_*` switch or a marker file for memory
- Keep the stop prompt's reply shape identical to `StopReview` in `scripts/core.ts`, or the reviewer JSON fails the schema and the stop check goes silent. On Claude Code a Stop `systemMessage` reaches the user only; on Pi the agent sees a nudge as `nextTurn`
- Any thrown review in the `UserPromptSubmit`, `PostToolBatch`, or `Stop` handler writes an empty tmpdir marker named by a SHA-256 of the session id, and those handlers return before `readTranscript` and the Codex call while it exists. `SessionStart` removes it, and on Pi the marker lives until the tmpdir is cleared. The classification is the throw, never the message text, so a transient failure also silences the session; the upgrade path is classifying the SDK error by type
- The taste handler's `try` wraps only the Codex call: a `.taste` write error reaches the entry-point catch and leaves the other reviews on
