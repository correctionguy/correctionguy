When fanning out over past conversations to build `.memory` (the `correctionguy:setup` skill, or any similar mining), the owner wants: focus on owner corrections, assumptions that turned out to be wrong, and not-so-obvious discoveries — a high-entropy memory stacked with historic lessons that are NOT easily readable from the codebase or other resources. Stated 2026-07-13.

**Why:** Low-entropy memories (facts re-derivable from the repo in minutes) waste recall context; the scarce value of transcripts is the lessons that live nowhere else.

**How to apply:** Put a triage stage before mining: sonnet grades each transcript's signal, miners run sonnet by default, and escalate fast (opus/top tier) when the triager flags valuable, high-signal content. At consolidation, drop anything a fresh agent could re-derive from the repo. Related: [[workflow-model-sizing-per-stage]], [[memory-files-live-in-repo-dot-memory]].
