# Codex

- `@openai/codex-sdk` vendors a codex CLI at the same version, and on the Codex login route the API 400-rejects a model newer than that CLI with "requires a newer version of Codex". Trivial calls pass on the outdated CLI, so only a realistic-size payload surfaces it. CI runs `scripts/codex-smoke.test.ts` through OpenRouter, where Codex strips one `provider/` prefix and gives a slug missing from its bundled `models.json` fallback metadata with empty `supported_reasoning_levels`, so a green CI run does not prove the vendored CLI knows the model. Before changing the default model, read the list at the SDK's tag: `curl -fsS https://raw.githubusercontent.com/openai/codex/rust-v<sdk-version>/codex-rs/models-manager/models.json | jq -c '.models[] | {slug, levels: [.supported_reasoning_levels[]?.effort]}'` [source: https://github.com/correctionguy/correctionguy/pull/74]
- A live check of a changed default model or effort runs with the overrides unset (`env -u CORRECTIONGUY_MODEL -u CORRECTIONGUY_MODEL_REASONING_EFFORT -u CORRECTIONGUY_SERVICE_TIER -u CORRECTIONGUY_FAST_MODE`), because a host that exports them makes the run test the override instead of the default. Confirm `.payload.model` and `.payload.effort` in the run's rollout `turn_context` record and the CLI in `session_meta` `cli_version` [source: https://github.com/correctionguy/correctionguy/pull/74]
- A broken review shows in the Codex rollout files (`~/.codex/sessions/<y>/<m>/<d>/rollout-*.jsonl` with `originator: codex_sdk_ts`) as `task_complete` with `last_agent_message: null` within seconds. Running the hook by hand with a real transcript prints the error on stderr
- A completed review's JSON reply is the assistant `response_item` record (`payload.type == "message"`, `payload.role == "assistant"`), not an `agent_message` event; extract it inside `jq`, because a multi-line reply breaks `tail -1`. A review on a tokenmaxxing seat writes its rollout under that seat's `CODEX_HOME`, not `~/.codex/sessions/`
- The stopgap for an outdated SDK in the Claude Code plugin cache is `bun add @openai/codex-sdk@<version> --ignore-scripts` inside `~/.claude/plugins/cache/correctionguy/correctionguy/<ver>/`, with the same exact pin in the repo `package.json`; see [[release]]
- `CORRECTIONGUY_MODEL_REASONING_EFFORT` is parsed by a `z.enum` in `scripts/codex.ts` at review time. Whenever `@openai/codex-sdk` is bumped, mirror its `ModelReasoningEffort` union in that enum: an effort the enum lacks throws inside the review and trips the session review breaker, so the plugin reviews nothing for the rest of the session
- Keep the conditional spread of `service_tier` in `codexOptions.config` in `scripts/codex.ts`. The SDK skips an `undefined` config value at runtime and throws on `null`, but its `CodexConfigValue` type excludes `undefined`, so `service_tier: env.CORRECTIONGUY_SERVICE_TIER` fails `bun run typecheck` with TS2322 and the only other form is a cast over the SDK type [source: https://github.com/correctionguy/correctionguy/pull/56]
- Construct `new Codex(...)` inside `runJsonReview` in `scripts/codex.ts`, never at module scope. The constructor resolves the vendored CLI binary and throws "Unable to locate Codex CLI binaries" when it is missing; at module scope that throw breaks every hook entry point and the Pi extension import, while inside the review it reaches the handler catch and turns off only the reviews
- The Codex model catalog (`codex debug models`, cached at `~/.codex/models_cache.json`) advertises `supported_reasoning_levels` and `service_tiers` per model, and the CLI rejects a `service_tier` the active model does not advertise. No `standard` tier value exists: the standard tier is the absent key, which `scripts/codex.ts` sends unless `CORRECTIONGUY_SERVICE_TIER` is set. `fast` is a legacy alias for `priority`
- Codex `sandboxMode: "read-only"` (the default unless `CORRECTIONGUY_YOLO=1`) blocks writes and network, not reads: every non-danger mode grants whole-filesystem read, and `workingDirectory` does not confine reads. The stop prompt therefore tells the reviewer to read `transcript_path` and treats a denied or missing file as best effort [source: https://github.com/openai/codex/blob/main/codex-rs/linux-sandbox/src/landlock.rs]
