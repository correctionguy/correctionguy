# AGENTS.md

Repo-specific notes only. General working discipline is not repeated here. Background facts live in `.memory/`, indexed by `.memory/MEMORY.md`; load one when its topic comes up.

correctionguy ships one plugin for two hosts, Claude Code and Pi (pi.dev), plus an [Agent Plugins](https://agent-plugins.org/) 1.0.0 portable core (root `plugin.json` + `skills/`) for other compatible clients. The Claude Code hooks run as subprocesses; the Pi extension runs in-process. Cursor is retired: the repo carries no Cursor adapter, manifest, hook file, or prompt set, and Agent Plugins clients get the skills only.

# Agent documents

- This file is the only instruction file, and every host reads it directly: Claude Code reads `AGENTS.md` when the project has no `CLAUDE.md` (see `.memory/claude-code-reads-agents-md.md`), Pi and Codex read it natively. Never add a `CLAUDE.md`, `.claude/CLAUDE.md`, or `.cursor/` file: a project `CLAUDE.md` switches Claude Code's `AGENTS.md` reading off, and a root `CLAUDE.md` fails `claude plugin validate --strict`.
- Agent documents outside `.memory` (this file, `skills/*/SKILL.md`, `README.md`) stay under 500 lines combined.
- `.memory` is the canonical memory location, tracked and public. Each file is one bare present-tense lesson that prevents a future mistake, with `name`, `description`, and `metadata.type` frontmatter: no dates, plugin version history, incident narratives, superseded text, or device, account, and environment details. History lives in git. Host memory directories are symlinks into `.memory` (Claude Code: `~/.claude/projects/<slug>/memory`, laid out by the setup skill), never the reverse.

# Traps

- Local dev is Bun, but the Pi import graph must run under Node: Pi loads extensions via jiti, not bun. Bun-only APIs (`Bun.env`, `Bun.file`, `Bun.stdin`) stay out of every module `scripts/pi-extension.ts` reaches (`core.ts`, `codex.ts`, `correctionguy.ts`, `prompts.ts`, `pi-adapter.ts`). The Claude Code hook entry point, `validate.ts`, and the tests are launched by `bun` and use Bun APIs. `Bun.write` ignores the `mode` option for string data, so a file that needs `0o600` is written with `node:fs/promises` `writeFile`. `scripts/codex.ts` must read `process.env`; reverting it to `Bun.env` silently breaks the Pi host while Claude Code keeps working.
- `@earendil-works/pi-coding-agent` is managed by hand, never via `bun add`: a `peerDependencies` entry of `"*"` plus a `devDependencies` copy for local `tsc`. Keep it out of `dependencies`, which would double-bundle what Pi already provides. The Pi manifest is the `pi` field in `package.json` (`extensions` and `skills`), and `scripts/validate.ts` checks those paths exist. Pi loads only what the manifest lists, so `skills/` reaches Pi through `pi.skills`, and Pi exposes each skill as `/skill:<name>`.
- Hook entry points are the one sanctioned catch boundary: they log to stderr and exit 0 so a plugin failure never breaks the host session. Everywhere else, fail fast and visibly.
- Every `CORRECTIONGUY_*` env var is optional. The plugin must never crash at load over env; a missing var degrades its own feature at the use site.
- On hosts with tokenmaxxing installed, the reviews borrow a pooled codex account: `scripts/codex.ts` runs `tokenmaxxing seat --codex <pid>` at review time and passes the printed store as `CODEX_HOME` to the Codex SDK (`env` replaces the wholesale `process.env` copy, so the child env must be rebuilt with the override). A missing binary, a non-zero exit, an empty reply, or a malformed `CORRECTIONGUY_TOKENMAXXING` value falls back to the ambient login (the flag parse sits inside the borrow's `try`, so a bad value disables the borrow and never the review); a non-zero exit echoes the seat command's stderr as one `correctionguy: tokenmaxxing seat:` line on the hook's stderr. `CORRECTIONGUY_TOKENMAXXING=0` opts out; it is parsed at call time, not in the module-scope schema, because the Pi host sets its own default (`pi-extension.ts` sets `??= "0"`: a borrow keyed to the long-lived Pi process would pin a pooled account for the whole chat) and the schema parse runs at import, before extension code executes. The borrow contract lives in tokenmaxxing's `docs/content/docs/codex.mdx`; the presence record keyed to the hook's pid is what keeps tokenmaxxing from placing a session on the borrowed account or refreshing its store mid-review, so never bypass it by pointing `CODEX_HOME` at `codex-stores/` directly.
- A repo fix does not reach Claude Code users until a release plus a plugin update: the plugin cache (`~/.claude/plugins/cache/correctionguy/correctionguy/<ver>/`) carries its own `node_modules`.
- Never smoke-test Codex with a trivial call. Trivial calls pass on an SDK whose vendored CLI is too old for the requested model; only realistic-size payloads surface the 400, and hooks swallow the error and exit 0, so breakage looks like the plugin doing nothing. See `.memory/codex-sdk-version-gates-new-models.md`.
- Claude Code fires `PostToolBatch` inside subagents with `agent_id` set, but `transcript_path` still names the parent session file, and a plugin `Stop` hook never fires inside a subagent. The Claude entry point must resolve `<session-id>/subagents/**/agent-<agent_id>.jsonl` itself; reading `transcript_path` there reviews every sibling in a fan-out against the parent's context and fires them all on the parent's batch count. See `.memory/claude-subagent-hooks-carry-parent-transcript-path.md`.

# Local rules that override the global ones

- Never add comments. If you see one, delete it.
- Never add helper functions to deduplicate, including inline closures created only to dedupe; use es-toolkit or duplicate the few lines. When cyclomatic complexity trips the linter (max 20), hoist repeated `||`/`??` expressions into single consts first. A single-purpose, called-once function is a last resort permitted only when the logic still cannot be inlined under that limit: `currentTodos` in `scripts/core.ts` is the one sanctioned instance. Do not flag it.
- Model-facing strings in `scripts/prompts.ts` must not contain em-dashes themselves. The sole sanctioned em-dash in this repo is the `MEMORY.md` index line separator defined in the setup skill.

# Verification

No CI, by design. `bun run check`, `bun run typecheck`, and `bun run validate` run locally, and the lefthook pre-commit gate is the only enforcement that exists: never route around it (`--no-verify`, `LEFTHOOK=0`), because the smoke test inside it is the sole guard against silent Codex SDK breakage.

`bun run test` round-trips a real Codex review against the live API on every pre-commit. That spend is pre-approved; no other metered run here is. The Codex SDK reads `~/.codex/auth.json`, not `OPENAI_API_KEY`, so an unauthenticated machine fails every commit until `codex login` runs there. The other test files cover the Stop nudge dedupe and the session review breaker and need no network. Hook logic is validated in the owner's live sessions, so never kill a running Claude Code or Pi process.

To exercise a hook without a host, pipe a JSON payload on stdin: `echo '{}' | bun scripts/correctionguy-hook.ts SessionStart` prints the preamble. `HookInput` rejects `transcript_path: null`; omit the key instead. `bun run check` needs Node 22.18 or later to load the `.ts` config files, and `bun run validate` shells out to the `claude` CLI, which is not a bun dependency and is installed separately.

# Changing prompt behavior

The prompts define six failures (unverified assumption, missed requirement, integration error, regression, wrong file, no reviews) and nothing else. An owner preference or repo procedure (ship steps, model sizing, task tracking, reporting style, memory layout) never goes into the prompt text; the reviewer reaches it through the instruction files named per host in `instructionFiles`, so a new location a host loads goes into that list, not into a flag. Keep in sync: the prompt content in `scripts/prompts.ts` (SESSION_START plus the per-host `stopPrompt`/`liveMonitorPrompt` builders behind CLAUDE_PROMPTS and PI_PROMPTS) plus `skills/correctionguy/SKILL.md`. The reviewer prompts name the agent under review per host (Claude, Pi) and the host's instruction files; never hardcode "Claude" into shared reviewer text. The skill mirrors only the agent-facing discipline and carries no reviewer ruleset, so a change confined to reviewer-side detection needs no skill sync. The plugin's own live monitor heuristically flags every `prompts.ts` edit as "siblings not synced"; verify against the skill before acting on it. `.memory` layout mechanics belong in `skills/setup/SKILL.md`, not in the preambles. Convention-override procedure belongs in `skills/actually/SKILL.md` (`/correctionguy:actually`; user-only); Pi loads it natively through `pi.skills` as `/skill:actually` and honors `disable-model-invocation`. Do not re-add `commands/correctionguy.md`: Claude Code treats a same-named command and skill as one `/correctionguy`, and the skill is the sole on-demand surface.

# Releasing

Bump the version in all three manifests in lockstep (`plugin.json`, `package.json`, `.claude-plugin/plugin.json`); `bun run validate` fails on a mismatch. Root `plugin.json` is the Agent Plugins 1.0.0 portable manifest (skills under `skills/`); `.claude-plugin/` stays as the host layer for Claude Code hooks and marketplace. Releases are GitHub-only, with no npm publish. Full steps in `.memory/release-process.md`.
